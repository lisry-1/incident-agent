# 简历项目表述与实现归属

## 可使用的项目条目

**Incident Agent — 服务故障诊断与受控处置平台**
TypeScript / Node.js / Pi Agent Runtime / Python / Docker / Kubernetes / Prometheus / Loki / Jaeger

- 基于 Miniclaw / Pi 二次开发分阶段故障诊断流程，实现指标探活、深层证据查询与时间线生成；接入 Prometheus、Loki、Jaeger 和 Kubernetes 只读适配器，通过 trace_id、pod_uid 对齐本地实验的日志、链路与事件。
- 实现 Harness 查询范围校验、请求预算、重复失败熔断及追加式 JSONL 审计；在独立 Docker 诊断容器中限制网络、文件写入与凭据访问，经可信 Broker 提供固定查询及模型接口。
- 实现证据和目标摘要绑定的 Ed25519 提案/人工批准机制，以及执行前持久化的一次性消费记录；验证受控容器重启与 Deployment 配置回滚，通过实例身份、模板摘要、Pod Ready 和实际 HTTP 响应核验动作结果。
- 构建 8 个公开固定回归用例，记录模型原文、工具轨迹和版本摘要；定位并修正输出契约歧义与重复键漏检，保留时间比较失败，形成“原始结果—程序复核—文字评审”的可追溯验收记录。

如果篇幅只够三点，可将评测并入第一点；无需为了增加数字占用简历。面试能解释并复现上述实现，比写“精通”更有说服力。

## 数字的使用边界

- 8 个用例：真实存在，4 例工具流程、4 例证据回放，均为公开合成回归集。
- 首轮提示词 3/8；v1.1 原自动输出 7/8；补上重复键漏检后，同一原始回答离线复核 6/8，分别记录，不拼成 100% 通过。
- 该批记录中的越权尝试、越界执行均为 0，分母仅这 8 例；case-04 通过主动拒绝，没有实际越界查询。不能改写成生产系统安全率 100%。
- 17 是 v1.1 的模型请求数，18 是三个诊断用例合计的领域工具调用数，二者不能混用。
- 不报告生产定位准确率、生产 MTTR、性能提升或参考作者的指标。

## 实现归属与面试准备

Miniclaw 工作台、Pi 基础循环、通用工具、Session/Memory、Skills/MCP 等底层能力来自开源基线。上述故障领域模块与实验流程是二次开发范围，由 Codex 辅助编写、调试，维护者完成本地操作和验证。不要把整套上游框架说成从零独立实现。

面试先讲一条自己能打开文件说明的链路，再讲验证证据和已知限制。参见 [面试讲解](INCIDENT-INTERVIEW.md)。项目进入本地演示交付版；不要求为投递继续增加业务功能，后续改进作为独立迭代。
